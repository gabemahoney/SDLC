# Documentation writing guide (Apiary default)

Apiary uses this file when no user copy of `guide:doc-writing-guide.md` is found as `~/.apiary/system/workflow.md` describes.

## Documents to keep current

- Keep the README useful as the Project's introduction and entry point for installation, setup and use. Link to detailed user guides and references in `docs/` or the Project's existing documentation location.
- Keep architecture documentation current with the system's components, interactions and design decisions. Use the Project's existing architecture docs, or `master_plan.md` if it has none.
- Keep developer and operational guides current where the Project needs them, including configuration, testing and release instructions.

Document what the software actually does. Add a document only when readers need information that has no suitable home, so the documentation stays easy to navigate.

## Write and trim

Use short, plain sentences. Lead with what the reader needs to know, and keep only details that help them understand or act.

Explain each fact in one place and link to it elsewhere, because repeated explanations drift. Update changed behaviour and remove outdated or duplicated passages and documents. Trimming and deletion matter as much as adding text.
